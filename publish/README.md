# publish/ — набор к публикации

Две папки, как просили: **методология Next Move Theory** отдельно и **прогон по МФЦ
Клинике** отдельно. Всё внутри — статические файлы без сборки, зависимостей и внешних
запросов: открывается двойным кликом по `index.html` и разворачивается на любом хостинге
как есть.

```
publish/
├── index.html              общая точка входа, две карточки
├── _config.ts              конфиг Lume (если сайт на Lume)
├── _build/render-md.mjs    пересборка .html из .md
├── next-move/              МЕТОДОЛОГИЯ — публиковать можно
│   ├── index.html          что читать и когда, порядок операций, анти-паттерны
│   ├── method.md/.html     правила для агента (файл CLAUDE.md / AGENTS.md)
│   ├── skills.md/.html     восемь скиллов и два контракта — описание
│   └── canon/              23 файла канона + README с лицензией
└── mfc/                    КЛИНИКА — закрыть доступом
    ├── index.html          точка входа: что изменила CRM, цепочка v2, архив v1
    ├── NOTICE.md/.html     что внутри чувствительного и что с этим делать
    ├── diagnose/ market-research/ craft-value-proposition/
    │   product-requirements/ go-to-market/     шесть документов, v1 и v2
    ├── concepts/plan.html  лендинг v2 «план с фикс-ценой» — прототип
    ├── concepts/razbor.html лендинг v1 «Разбор» — прототип
    ├── job-graph.html      граф задач клиники
    └── obzvon-guide.md/.html гайд обзвона: принципы, вопросы, скрипты
```

## Доступ — прочитайте до деплоя

Папка `mfc/` — **коммерческая тайна клиники**: выручка, фамилии врачей с оборотами,
разбор оттока, реальные цены и телефон. Разворачивайте её только за паролем (basic-auth,
приватный деплой, ссылка по токену) — либо публикуйте одну `next-move/`. На всех
страницах стоит `noindex, nofollow`, но это просьба к поисковику, а не защита. Подробно —
[`mfc/NOTICE.md`](mfc/NOTICE.md).

Персональных данных пациентов в наборе нет: пофамильные списки на обзвон никогда не
попадали в git и передаются клинике напрямую.

Папка `next-move/` содержит чужие тексты под лицензией
[CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/) — автор Иван
Замесин. Условие NC значит: нельзя размещать так, чтобы канон работал как часть
коммерческого материала. Отдельная страница с указанием авторства и ссылкой на
[исходный репозиторий](https://github.com/zamesin/Next-Move-Theory-Canon-and-Skills) — в
порядке.

## Как разворачивать

**Любой статический хостинг** — nginx, GitHub Pages, Vercel, Netlify, S3. Содержимое
`publish/` кладётся в корень или в подпапку, ничего собирать не нужно. Локальный
просмотр:

```bash
npx http-server publish -p 8080     # или python3 -m http.server -d publish 8080
```

**Lume** — два варианта:

1. *Самостоятельный сайт.* `_config.ts` уже лежит в папке: `deno task lume --serve`.
2. *Внутрь существующего сайта на Lume.* Скопируйте `next-move/` и `mfc/` в свой `src`
   и добавьте в свой `_config.ts`:

   ```ts
   site.copy("next-move");
   site.copy("mfc");
   ```

   Наш `_config.ts` в этом случае не нужен — удалите его.

## Что развёрнуто сейчас

Проект **`mfc-nmt-docs`** в команде `art's projects` на Vercel:
`https://mfc-nmt-docs-arts-projects-362cad37.vercel.app`

Устроено так:

- **Сборка тянет содержимое из этого репозитория.** В проекте лежат три файла —
  `build.sh`, `middleware.ts`, `package.json`; `build.sh` клонирует ветку
  `claude/next-move-theory-skills-a37whv`, копирует `publish/` в `out/` и выкидывает
  служебное (`_build`, `_config.ts`, `README.md`). Build command — `bash build.sh`,
  output directory — `out`.
- **Доступ закрыт HTTP Basic Auth** на edge-middleware: `middleware.ts` с матчером
  `/(.*)` отдаёт `401` на всё, пока не пришли верные логин и пароль. Пароль **не хранится
  в этом репозитории** — он вшит в `middleware.ts` внутри проекта Vercel. Поменять —
  через редеплой с новым значением.
- **Штатная пароль-защита Vercel не используется**: Advanced Deployment Protection —
  платный аддон, на текущем тарифе он выключен. Vercel Authentication (вход по аккаунту
  Vercel) на проекте отключён — иначе она перехватывала бы запрос раньше middleware, и
  открыть ссылку смог бы только владелец аккаунта.

Обновить содержимое = сделать новый деплой: сборка каждый раз клонирует ветку заново.
Автодеплоя по пушу нет — репозиторий не подключён к Vercel через GitHub-интеграцию.

**Если репозиторий станет приватным** — сборка сломается: `git clone` без токена перестанет
работать. Тогда либо подключите репозиторий к проекту через GitHub-интеграцию Vercel
(она умеет приватные), либо положите токен в переменную окружения и подставьте его в URL
клона внутри `build.sh`. Уже собранный деплой при этом продолжит работать — он статичен.

## Как пересобрать .html из .md

Markdown лежит рядом с HTML: править удобнее `.md`, а читать в браузере — `.html`.
После правки:

```bash
npm i marked@14
node publish/_build/render-md.mjs
```

Скрипт проходит по всем `.md` внутри `publish/`, рендерит их в `.html` рядом и
переписывает ссылки вида `foo.md` в `foo.html`. Служебную папку `_build` и скрытые файлы
пропускает.

## Что здесь не так, если смотреть строго

- **Ссылки внутри документов v1 и v2 ведут внутрь набора** — на внешние источники
  (приватный репозиторий аналитики `mfc-clinic-analytics`) ссылок нет намеренно: он
  приватный, и в нём лежат данные, которых здесь быть не должно.
- **Прототипы страниц — прототипы.** На `concepts/plan.html` и `concepts/razbor.html`
  висит баннер и жёлтые метки `[ПРОВЕРИТЬ]`; как живые страницы их публиковать нельзя до
  сверки цен и юридической проверки (реклама медуслуг: обязательное предупреждение о
  противопоказаниях не менее 5% площади, штраф юрлицу 200 000–500 000 ₽).
- **Все выводы — гипотезы языковой модели.** Цифры, помеченные источником, измерены по
  выгрузке CRM; остальные требуют проверки. Вердикт цепочки — `GO (к проверке)`.
