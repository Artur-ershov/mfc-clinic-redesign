# Интеграция с МИС IDENT (АйДент)

Шлюз, через который клиника видит заявки с сайта прямо в своей программе, а мы
получаем расписание врачей. Живёт на `lume.moscow`, исходники — в
[`redesign-mfc/ident/`](ident/).

## Что вписать в АйДенте

Настройки → Интеграции → Добавление внешнего сервиса → Сервис: **Собственный
сервис клиники**.

| Поле | Значение |
|---|---|
| Название | `Сайт МФЦ Клиники` |
| Роли для автозапуска | Администратор *(и Директор, если его компьютер работает дольше)* |
| Тип подключения | `HTTP` |
| URL | `https://lume.moscow/mfc/ident` |
| Ключ доступа | `8d45a5b12988cc9fb9e5a0be9a8df38d` |
| Тип сериализации | `JSON` |
| Максимальный период отчета в днях | `30` |
| Лимит на запрос | `500` |
| Таймаут | `45` (по умолчанию) |

Переключатели на первом шаге: **Выгрузка расписания — Вкл**, остальные два —
**Выкл**. Сначала только забираем данные и смотрим, что приходит; отдавать
заявки в МИС будем отдельным решением.

Это же продублировано на нашей стороне: в `config.php` стоит
`'tickets_enabled' => false`, и `GetTickets` отдаёт пустой список независимо от
того, в каком положении тумблер в программе. Заявки при этом копятся в очереди —
когда флаг включим, IDENT заберёт накопленное разом за «максимальный период
отчета».

URL — без завершающего слэша и без имени метода: программа сама добавляет
`/GetTickets`, `/PostTimeTable` и остальные.

## Направление потоков

У IDENT нет веб-сервера, и обращения к его базе снаружи невозможны: все запросы
инициирует «Клиент» — запущенная копия программы на компьютере в клинике.
Поэтому интеграция работает, **только пока этот компьютер включён и программа
открыта**, а данные ходят так:

| Метод | Кто инициирует | Что передаёт | Частота |
|---|---|---|---|
| `GET /GetTickets` | IDENT → к нам | заявки с сайта | 2 мин |
| `GET /GetFinishedCalls` | IDENT → к нам | завершённые звонки | 180 мин |
| `GET /GetOngoingCalls` | IDENT → к нам | звонки в моменте | — |
| `POST /PostTimeTable` | IDENT → к нам | расписание на 30 дней вперёд | 10 мин |

Единственный поток, где данные идут из клиники наружу, — расписание: филиалы,
врачи, слоты и признак занятости. Ни пациентов, ни визитов, ни сумм этот канал
не отдаёт — историю и выручку берём выгрузкой отчётов в Excel, см.
[CRM-DATA-REQUEST.md](../analytics/insights/CRM-DATA-REQUEST.md).

Спецификация: [вариант с HTTP](https://help.dent-it.ru/help/variant-s-http),
[структура объектов](https://help.dent-it.ru/help/struktura-peredavaemykh-obektov).

## Как устроено у нас

```
форма на сайте → site/send-lead.php ─┬→ почта + телеграм (как раньше)
                                     ├→ site/leads/leads.ndjson (страховка)
                                     └→ ident/data/tickets.ndjson ← GET /GetTickets
IDENT → POST /PostTimeTable → ident/data/timetable-latest.json
                              ident/data/timetable/YYYY-MM-DD.json (история загрузки)
```

- Авторизация — заголовок `IDENT-Integration-Key`, сверка через `hash_equals`.
  Всё, кроме 401/403, отдаётся кодами 4XX/5XX: возвращать ошибку с кодом 2XX
  спецификация запрещает.
- Каталог `ident/data/` закрыт от HTTP (`Require all denied`) — там телефоны.
- Состояние «уже отдано» не храним: IDENT отбрасывает дубли по `Id`, поэтому
  отдаём всё, что попало в запрошенное окно.
- Отсев записей без телефона делается **до** нарезки на страницы. Иначе
  неполная страница читается программой как «данные кончились».
- Заявки без распознанного телефона в IDENT не уходят: `ClientPhone` —
  обязательное поле, а поле «контакт» на сайте свободное, туда пишут и телеграм.
  Такие заявки по-прежнему приходят в почту и телеграм, счётчик — в
  `ident/data/access.log`.

## Проверка

```bash
curl -s https://lume.moscow/mfc/ident/
```

Что доехало — сводка `Status` (её вызываем только мы, IDENT про неё не знает):

```bash
curl -s -H "IDENT-Integration-Key: 8d45a5b12988cc9fb9e5a0be9a8df38d" https://lume.moscow/mfc/ident/Status
```

`timetable.received: null` означает, что расписание ещё ни разу не приходило.

Пробная заявка, которая проходит весь путь, но не шлёт уведомления:

```bash
curl -s -X POST -H "Content-Type: application/json" -d '{"probe":"80d6c9b920abfe171e0bbb20","name":"Тест","contact":"+79852345678","consent":true,"source":"hero"}' https://lume.moscow/mfc/site/send-lead.php
```

После проверки очередь чистится заливкой пустого `tickets.ndjson` в
`mfc/ident/data/` — иначе тестовая заявка уедет в программу как настоящая.
